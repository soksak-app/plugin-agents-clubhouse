(3) card 위 배치(C4). 대기: core F1062-3(host가 `core.session.*`과 `core.sessions`를 구현한다. 그 전까지 room은 session을 열 수 없다), terminal plugin F1062-4(core가 각 session의 plugin에 요구하는 `sessions` 선언), 에이전트 작업공간 F1045-4(`agents.definitions` extension point), A5(그룹의 member).

- [o] C7 — P1: project data store가 오류를 빈 값으로 바꾸지 않고 보고한다. 입력: `src/room/persona.ts`의 `createPersonaStore`와 `src/room/session-store.ts`의 `createMemberSessionStore`가 실패한 `data.get`을 `null`로 바꿨다(`.catch(() => null)`). 그래서 페르소나 읽기 실패는 빈 텍스트로, 세션 읽기 실패는 세션 없음으로 보였고 실패가 사라졌다. `ensure`도 실패한 `data.define`을 버렸다(`.catch(() => undefined)`). 기대: define, read, write 실패는 data API의 오류로 거부되어, 호출자가 view 오류 기록(`runtime.error`)으로 보고한다. page는 이를 application log에 `error: <where>: <text>`로 쓴다. 문서가 없는 것은 여전히 빈 텍스트나 `null`로 읽는다. 정상 상태이기 때문이다. define 실패는 거부된 promise로 남기지 않고 다음 호출이 다시 시도한다. 결과: `createPersonaStore`와 `createMemberSessionStore`는 data API의 오류로 거부한다. `ensure`는 거부된 define을 버려서 다음 호출이 다시 define한다. 테스트 `src/room/persona.test.ts`와 `src/room/session-store.test.ts`(신규): Red는 4건 실패로, 삼킨 값 `''`와 `null`이 관찰되었다.
