# Features

[English](features.md)

- [o] C1 — P1: plugin의 manifest가 현재 core 형식이다. 입력: `plugin.json`이 제거된 멤버 `permissions`, `entry`, `configuration`, `contributes`, `programs`와 이전 형식의 `views`, `commands`를 썼으므로 core 검사가 `plugin.json: unknown field configuration`으로 거부했다. 기대: 현재 형식(`docs/spec/plugins.md#pluginjson`, core)의 멤버를 쓴다. view `surface`와 그 page, `mark`, `icon`, `preview`, 형식이 정해진 `settings`, 방의 커맨드와 element를 담은 `exposes`를 두고, `soksak-plugin-agents-acp` 의존은 C6까지 유지한다. 결과: core 검사(`validateManifest`)가 파일을 받아들인다. `src/host-contract.test.ts`의 manifest 시험은 현재 형식을 확인하며, 현재 형식에 `permissions` 멤버가 없으므로 `permissions` 게이트 시험은 지운다. `npm test`와 `npm run typecheck`가 통과한다. page `ui/clubhouse.html`은 아직 저장소에 없으며 C2가 만든다.
  - 커맨드 결과 스키마는 지금 `{type: "object"}`이다. C2가 각 결과의 정확한 형태를 정한다.
  - 이전 `configuration`의 enum 이름(`enumLabels`)은 현재 형식에 없다. 그 한국어 이름은 설정 설명에 적었다.
- [ ] C2 — P0: 방이 자기 view page에서 돈다. 입력: `src/main.ts`가 제거된 host API(`app.commands.register`, `app.ui.registerView`, `app.bus`, `app.settings`, `app.data`, `app.fs`)를 호출하므로 현재 core에서 방의 어떤 부분도 시작하지 않는다. 기대: `ui/clubhouse.html`이 view surface의 page이며 `src/main.ts`의 bundle을 불러온다. `exposes`의 커맨드는 page에서 실행하고, `exposes.element`의 element 이름은 공용 binder로 연결한다. persona, 멤버 session, trace, 매크로의 project data는 `data`로 선언하고 surface context로 읽는다. 이전 `roster` view의 로스터는 방 page에 그린다. `package.json`의 `files`가 page와 bundle을 담아 plugin pack이 release를 받아들인다. 대기: 없음.
- [ ] C3 — P0: 소환은 고른 member마다 owned session을 시작한다. 입력: 방이 member를 화면에 띄울 방법이 없다. 기대: 방은 정의를 agents plugin의 extension point `agents.definitions`에서 읽고(에이전트 작업공간 F1045-4), 소환할 때 member마다 `core.session.open`으로 방 surface의 owned session을 연다. tab은 필요 없다. member와 session의 연결은 project data에 저장하고 재시작 뒤에도 남는다. 대기: core F1062-3(owned session 커맨드), terminal plugin F1062-4(`sessions` 선언), 에이전트 작업공간 F1045-4(`agents` plugin과 extension point).
- [ ] C4 — P0, 에이전트 작업공간 F1045-8과 연결: member를 보여 줄 때 배치를 먼저 계획한다. 입력: member는 owned session으로 시작하며 card가 없다. 기대: 방은 방 group card와 member를 담은 tree로 `core.layout.plan {tree}`를 호출한다. 계획이 `feasible`이면 `core.layout.apply`로 지어 member를 방 group card에 넣고 plane을 나눈다. 아니면 member를 방 card의 tab으로 열고, core의 공용 표시 경로로 계획의 `reason`을 알린다(응용 log의 `error: <where>: <text>`). 대기: C3.
- [ ] C5 — P0: member 사이의 message를 terminal로 전달한다. 입력: 방은 입력과 스트리밍에 ACP(`soksak-plugin-agents-acp`의 `acp.*` 커맨드)를 썼다. 기대: 방은 입력을 terminal의 submit 커맨드로 보내고, 차례의 끝은 terminal이 선언한 program 상태 status(`done` 또는 `idle`)로 받으며, 답은 session id를 준 core conversation read로 읽는다. 방은 terminal 화면, sidecar, CLI의 session 파일을 읽지 않는다. 대기: C3; terminal plugin의 submit 커맨드와 status(terminal 저장소의 checklist); 에이전트 작업공간 계획의 core 계약 변경 4(conversation read가 session 폴더와 session id를 받음).
- [ ] C6 — P1: 방에서 ACP를 뺀다. 입력: `src/engine.ts`, `src/room/acp-shapes.ts`와 `plugin.json`의 의존 `soksak-plugin-agents-acp`가 ACP로 방을 구현한다. 기대: ACP 코드와 의존을 지우고 C5의 message 전달이 그 자리를 잇는다. 방이 C5 전까지 ACP 커맨드를 부르므로 의존은 이 항목에서 지운다. 대기: C5.
