# Changelog

## Unreleased

- C2, C6: The room runs on its view page (`ui/clubhouse.html`) with the commands, elements, status and project data of `plugin.json`. The ACP engine, its dependency and the commands that used it are removed, so the room has no member transport until C3 and C5.
- C7: The project data stores (`createPersonaStore`, `createMemberSessionStore`) reject with the error of the data API instead of returning an empty text or `null`. A failed define is retried by the next call. Their tests cover the failures (`src/room/persona.test.ts`, `src/room/session-store.test.ts`).
- C5: The member message relay (`src/room/relay.ts`) sends a room message with the declared `terminal.submit` command and takes the end of the turn from the declared `terminal.program` status. It refuses a send while the member waits or is not running. The port to a member terminal and the answer read are not built yet (C5 stays open).
- C8: The tower rethrows a failed `data.define` in the macro and trace stores (the next call defines again) and a failed `status.query` in the domain map, instead of swallowing them. A `status.query` reply without `statuses` is refused.
- C9: The tower and the room report or rethrow every caught error through `room.report` (`error: <where>: <text>`). The trace store reports failed writes and continues; the confirm token needs `crypto.getRandomValues` (no `Math.random` fallback); unserializable step params refuse the scan; the modal and the theme listener report their failures.
- C10: A destructive batch is refused before its first step when its rollback snapshot cannot be captured (`SNAPSHOT_FAILED`), and the failure is reported. Batches without a destructive step still run.
- C11: A failed palette run, plan, or plan edit reports its code and reason through `room.report` (`error: <where>: <code>: <reason>`), not a generic phrase.
- C3: Summoning opens each checked member as an owned session (`core.session.open`) and stores the member-to-session relation in project data. `plugin.json` declares no `sessions` and depends on no sidecar: core refuses an open only for a plugin that declares no sessions. The open call takes `size` (`{width, height, scale}`) instead of `cols` and `rows`, and a stored session is reused only while `core.sessions` lists it as open. The definitions source and the trigger are not wired yet (C3 stays open).
- C12: The room shows each failure through the window error display (`tab.error`), and records a refused display through `runtime.error`.
- C4: The room plans the arrangement of its room card and member cards with `core.layout.plan`, applies a feasible plan with `core.layout.apply`, and opens the members as tabs of their owned sessions with the plan's reason in the declared arrangement status otherwise. The call site after a summon is not wired yet (C4 stays open).
- Boundary: the room tests name the plugin that runs a member through a fixture id (`fixture-terminal`) that each test declares, not a real plugin id. No room code holds a plugin id: the plugin of each member comes from its caller.
- C5: The room submits each message to its member's owned session with `core.session.submit`, reads the screen with `core.session.read` (shape checked), and reads the program state from `core.sessions`. The relay (`src/room/relay.ts`) submits only while the program is idle and ends the turn after working and idle again. The page wiring waits for C3-1 and the release of core F1062-7 (C5 stays open).
- C13: The room lists the agents plugin in `dependencies` and reads its status `agents.definitions` through `src/room/definitions.ts`, which refuses another form with an error that names the status and gives each definition its plugin and start values. Red: `src/room/definitions.test.ts` failed with `Cannot find module`. Green: 279 tests pass and the typecheck passes. The window check waits for core F1074.
- C14: The roster lists the agent definitions of the status `agents.definitions` through `rosterFrom` (`src/room/roster.ts`), which keeps the checked state and order and checks a new definition. Red: `src/room/roster.test.ts` failed with `Cannot find module`. Green: 282 tests and the typecheck pass.
- C3-1 and C4: A check of the roster summons the checked members with `summonMembers` and arranges the opened members with `arrangeMembers` (`src/room/trigger.ts`), one run after the other. The definitions come from the status `agents.definitions`. Red: `src/room/trigger.test.ts` failed with `Cannot find module`. Green: 287 tests and the typecheck pass. The live summon waits for core F1074.
